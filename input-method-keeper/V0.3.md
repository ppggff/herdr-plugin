# Input Method Keeper v0.3

Status: implemented on 2026-07-22; release validation completed.

Theme: **quiet, fast, and self-maintaining**.

Version 0.3 should make the existing pane-memory promise feel dependable over
long-running Herdr sessions. It is a maintenance release, not a feature
expansion. It keeps the current macOS-only scope, pane-memory behavior, two
backend choices, and `keep` / `reset` / `ignore` policy.

## Why This Release

The v0.2 runtime is healthy, but long-running evidence collected on 2026-07-21
shows avoidable maintenance and hot-path work:

- 68 unit and smoke-contract tests passed.
- 197 recent `pane.focused` commands all succeeded; p50 was 340 ms and p95 was
  542 ms.
- The current Herdr session had 39 live panes and 55 stored pane records, so 16
  records no longer described a live pane.
- Of 5,223 focus decisions, 4,231 were already on the requested input source
  and 987 performed a real selection.
- `focus.log` was about 2.3 MB and the active debug log was about 5.1 MB. Focus
  logging had no rotation, and rotated debug logs had no retention policy.

These numbers are a dated reference-machine snapshot, not release guarantees.
They show that focus correctness is working while lifecycle maintenance,
default noise, and repeated I/O deserve attention.

## Product Promises

Version 0.3 has four user-facing promises:

1. Normal pane-memory cleanup is automatic. Users do not need to run a command
   to keep ordinary current-session state healthy.
2. A pane-list omission is only a cleanup candidate. Automatic maintenance
   deletes a record only after Herdr also returns an explicit not-found result
   for that pane id; unavailable, malformed, partial, or ambiguous evidence is
   retained.
3. Focus optimization does not weaken stale-event protection or make the
   plugin select an input source for a pane that is no longer focused.
4. A new installation stays quiet by default and keeps its logs bounded.

## Self-Maintaining Pane Memory

### Immediate lifecycle handling

The existing event behavior remains the first line of maintenance:

- `pane.closed` removes one pane record.
- `tab.closed` removes records belonging to the closed tab.
- `workspace.closed` removes records belonging to the closed workspace.
- `pane.moved` migrates the record to the new public pane id.
- disabling the plugin or changing policy to `reset` or `ignore` clears the
  current session's pane memory.

These operations stay serialized by `run.lock` and continue to fail open when
required event fields are missing.

### Guarded automatic reconciliation

Lifecycle events can be missed while a plugin is disabled, during upgrades, or
across older Herdr behavior. Version 0.3 adds a low-frequency reconciliation
pass for the current Herdr session.

- State carries an optional `last_reconciled_at` timestamp. Its absence is
  compatible with existing version 1 state and means maintenance is due.
- Reconciliation becomes due after 24 hours. The interval is fixed in v0.3; it
  is not another user-facing setting.
- A successful `keep` focus decision finishes restoring the input source and
  performs its normal dirty/current-pane check before attempting due
  maintenance.
- The focus worker keeps `focus.lock`, attempts `run.lock` without waiting, and
  gives the entire maintenance pass a 250 ms budget. If the lock is busy or the
  budget expires, maintenance remains due and a later focus can retry.
- Under that single `run.lock` acquisition, the worker loads pane memory,
  obtains and strictly validates a socket `pane.list` response, confirms each
  unmatched stored id with socket `pane.get`, prunes confirmed-absent records,
  and saves state. The list query, absence confirmation, state load/mutation,
  and timestamp update must not be split across lock acquisitions.
- Pane-list parsing is all-or-nothing. A malformed pane entry invalidates the
  response; adapters must not silently filter bad entries into a shorter list.
- `pane.get` returns a tri-state result for maintenance: `present`, `absent`, or
  `unknown`. Only an explicit Herdr pane-not-found response produces `absent`.
  Timeouts, transport failures, invalid responses, and other errors produce
  `unknown` and retain the record.
- After maintenance releases `run.lock`, the worker repeats the normal
  dirty/current-pane check before releasing `focus.lock`. A focus event arriving
  during maintenance is therefore coalesced and restored by the existing
  worker rather than left as an unhandled dirty marker.
- Automatic reconciliation uses only the local Herdr socket. It does not spawn
  the Herdr CLI on a focus event.
- `last_reconciled_at` advances only after a successful live-pane query and
  successful resolution of every cleanup candidate. Confirmed-absent records
  may be pruned while unknown candidates are retained, but maintenance remains
  due when any candidate is unknown.

No current-session pane records are pruned when:

- the socket request fails or times out;
- the response is not a strictly valid pane list;
- the list is empty after a focus event that identified a current pane;
- the current focused pane is absent from the response; or
- state cannot be loaded or saved safely.

A nonempty partial list is also safe: every omitted stored id still requires an
explicit `pane.get` not-found response before pruning.

The next lifecycle event or due maintenance pass can retry. This prefers stale
data over destructive guesses.

### Inspection and recovery

Routine cleanup is automatic, but explicit tools remain useful:

- `status` and the dashboard show live, stored, unmatched, and missing counts.
  "Unmatched" means absent from the read-only list snapshot, not confirmed
  stale. "Missing" means a live pane id does not yet have stored pane memory;
  this can be normal for a new or not-yet-focused pane. These surfaces never
  repair, confirm absence, prune, or create state.
- `doctor` reports the reconciliation timestamp and explains why automatic
  maintenance is failing or still due. Its existing corruption-repair behavior
  remains limited to the doctor path.
- `doctor --gc-all` forces current-session reconciliation and then performs the
  existing age-based cleanup of other session directories. A failed live-pane
  query skips current-session pruning; it does not turn uncertain pane evidence
  into deletion. Independent age-based cross-session cleanup may still proceed.

No new public cleanup action is required for v0.3.

## Quiet Defaults

For newly created configurations:

- `notify_on_focus` changes from `true` to `false`.
- `pane_status_on_focus` remains `true`, but an unchanged, unexpired `ime`
  metadata token is not reported again.
- `focus_log` remains `true` so failures can be reconstructed, but the log is
  rotated and retained within a fixed budget.

Existing configuration files are not rewritten to adopt the new notification
default. A user who explicitly or historically has `notify_on_focus = true`
keeps that behavior after upgrade.

The compact dashboard remains read-only. It gains a small health summary:

- live / stored / unmatched / missing pane counts;
- last successful reconciliation and whether maintenance is due;
- backend health;
- current focus/debug log sizes and retained file counts.

An interactive settings pane and action-surface redesign remain future work.
Version 0.3 does not remove or rename existing action ids.

## Faster Focus Handling

### Correctness constraints

The following protections remain mandatory:

- session-scoped nonblocking `focus.lock`;
- `focus.dirty` coalescing when a focus worker is already active;
- debounce before selecting an input source;
- revalidation of the current pane after backend reads and before selection;
- global `run.lock` around state mutation and input-source side effects;
- bounded external calls and fail-open behavior; and
- whole-transition state commit only after target processing succeeds.

Performance work must not replace these rules with trust in the original event
pane id.

### Measured stages

Before removing I/O, the focus path records stage durations in structured debug
output:

- `lock_wait_ms`
- `stabilize_ms`
- `backend_current_ms`
- `backend_select_ms`
- `metadata_ms`
- `notification_ms`
- `total_ms`
- `coalesced_events`

This extends existing diagnostics; it does not introduce a metrics framework or
long-running process.

### Safe reductions

Version 0.3 then removes work at existing seams:

1. When focus handling has already read the backend input source for the
   previous-pane observation and revalidated focus afterward, it passes that
   known value into the ensure operation instead of launching the helper again.
2. `HerdrClient` centralizes socket requests and applies this fallback matrix:
   - correctness-critical `pane.current` uses socket first and one bounded CLI
     fallback when the socket request fails;
   - automatic reconcile `pane.list` / `pane.get` uses socket only, and any
     failure becomes unknown evidence with no unsafe deletion;
   - event-path metadata and notification writes use socket only and fail open;
     and
   - user-triggered status, dashboard, and doctor reads may use bounded CLI
     fallback.
3. Pane metadata publication is skipped when the focused pane already exposes
   the same `tokens.ime` value. A missing token, changed token, or expired TTL
   still causes a report.
4. Automatic reconciliation is never inserted before the input-source decision
   and is not performed on every focus.

### Reference-machine performance gate

Using the same machine and a 200-event sample:

- all sampled `pane.focused` plugin commands must succeed;
- the already-current path should have p95 at or below 400 ms;
- the selected path should have p95 at or below 650 ms, including helper
  refresh wait;
- rapid pane cycling must not select for a stale pane; and
- WeType Pinyin to ABC and ABC to WeType Pinyin must pass the real-backend smoke
  path.

The correctness checks are release requirements. The latency values are
reference-machine gates and should be recorded with the release evidence, not
presented as portable guarantees.

## Bounded Logs

One internal log module owns focus and debug log paths, append behavior,
rotation, and retention. The initial fixed policy is:

| Log | Segment size | Total segments including active | Maximum retained data |
| --- | ---: | ---: | ---: |
| Focus decisions | 5 MiB | 3 | 15 MiB |
| Debug events | 10 MiB | 3 | 30 MiB |

Rotation preserves `focus.log` and the current debug-log pointer so existing
status output and `tail -F` workflows continue to work. Retention never removes
state files, lock files, helper binaries, or corruption backups. Version 0.3
does not expose log-size tuning in `config.json`.

## Module Ownership

The existing dependency direction remains intact:

```text
cli
  -> focus
      -> records
      -> input_source
      -> herdr
      -> logs
  -> dashboard
      -> records
      -> herdr
      -> logs
```

- `focus` owns focus stabilization, lock ordering, coalescing, and the decision
  sequence.
- `PaneRecords` owns pane-memory schema, current-session audit/reconciliation,
  lifecycle mutations, repair rules, and semantic inspection projections.
- `StateStore` remains an internal persistence adapter for `PaneRecords`.
- `input_source` owns backend execution and the ensure-input-source operation.
- `HerdrClient` owns socket requests, the pane-presence tri-state, and the
  per-operation bounded fallback policy.
- `logs` owns focus/debug formatting, append, rotation, retention, and size
  inspection.
- `dashboard` renders read-only semantic projections and does not repair state.

No generic workflow engine, plan/result hierarchy, daemon protocol, or settings
framework is introduced.

## Compatibility and Migration

- The plugin id remains `ppggff.input-method-keeper`.
- The minimum supported Herdr version remains 0.7.4.
- Existing action ids, pane entrypoint, config/state directories, and backend
  configuration remain valid.
- `last_reconciled_at` is an optional addition to state version 1; no eager
  state migration is required.
- Existing config values win over new defaults.
- Automatic maintenance only reconciles the current socket-derived session
  key. Cross-session age cleanup remains a doctor operation.

## Delivery Order

Implement v0.3 as small observable slices:

1. Add read-only live-pane audit and dashboard/status health projections using
   "unmatched" rather than claiming unconfirmed records are stale.
2. Add forced current-session reconciliation to `doctor --gc-all`, including
   strict list validation and per-candidate `pane.get` confirmation.
3. Add guarded 24-hour automatic reconciliation after successful focus.
4. Give focus/debug logs one owner and enforce rotation/retention.
5. Add focus-stage timings without changing decisions.
6. Reuse validated backend state and add socket-first Herdr writes.
7. Skip unchanged metadata and apply quiet defaults for new configs.
8. Run the complete validation matrix and record reference-machine timings.

Each slice should preserve the public behavior of previous slices and be tested
through the owning module's interface.

## Release Acceptance

Version 0.3 is ready only when all of the following are true:

- Existing unit tests and smoke-contract tests pass.
- Tests cover lifecycle cleanup, audit, forced prune, due automatic reconcile,
  busy-lock retry, malformed/empty live-pane responses, a partial list that
  still contains the focused pane, unknown `pane.get`, and state-save failure.
- Tests prove every automatic-maintenance socket call consumes only the
  remaining shared 250 ms budget and only Herdr's explicit pane-not-found result
  maps to `absent`.
- Tests cover a pane-list snapshot followed by a concurrent focus commit and
  prove the single `run.lock` interval cannot prune the fresh record.
- Tests inject a focus event during automatic maintenance and prove the final
  dirty/current-pane check restores the newest focus before releasing
  `focus.lock`.
- Tests prove `status` and dashboard collection remain read-only.
- Tests prove automatic reconciliation is unnecessary for routine correctness
  and never runs before input-source restoration.
- Tests cover log rotation, retention, and `tail -F` compatible current paths.
- Socket failures use the intended fallback or fail open without unsafe state
  mutation.
- Rapid-focus fake-backend smoke passes without stale selection.
- Full real-backend smoke passes in both directions between two installed input
  sources.
- Upgrade validation preserves an existing config, state file, action ids, and
  helper backend binding.
- The release notes include the dated performance sample and explain that old
  configs retain their notification setting.

## Release Evidence

Validation completed on 2026-07-22 on the reference Mac with Herdr 0.7.4:

- 94 unit and smoke-contract tests passed.
- Base action/metadata smoke, complex three-pane fake-backend smoke, rapid focus
  storm, fake-backend E2E, and full real-backend E2E all passed.
- The real-backend run passed in both directions between
  `com.apple.keylayout.ABC` and `com.apple.inputmethod.SCIM.ITABC`, including
  `reset` and `ignore` actions.
- A 200-event sample completed with 100 successful events per path. The
  already-current path measured p50 237 ms, p95 254 ms, and max 340 ms. The
  selected path measured p50 275 ms, p95 283 ms, and max 413 ms.
- The latency numbers are reference-machine evidence, not portable guarantees.
- Upgrade compatibility keeps existing config values authoritative, so old
  configs with `notify_on_focus = true` remain noisy until the user changes
  them; only newly created v0.3 configs default to `false`.

## Non-Goals

Version 0.3 does not add:

- a daemon, LaunchAgent, or long-running input-source observer;
- cross-application input-method control;
- per-workspace, per-project, per-agent, or cwd rules;
- an ignore-list or general rule engine;
- Linux or Windows support;
- a Swift rewrite of the plugin;
- an interactive settings TUI; or
- a new public cleanup command.
